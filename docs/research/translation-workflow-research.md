# 번역 워크플로우의 관찰과 검증: 연구 조사 및 적용안

조사일: 2026-11-12. 상태: 조사 문서 보관. 구현·실험 실행 및 math2phys 적용은 보류. 기존 하네스 소스는 아직 열람하지 못했으며 아래 필드와 경로는 신규 제안이다. 논문 재현 실험·모델 실행은 수행하지 않았다.

## 목적과 판단

영문을 한국어로 정확하게 옮기는 작업에서, 결과를 개선하는 중간 작업을 찾아 기록하고 재사용한다. 장기 목적은 한국어 화자가 그 절차를 배워 영어 문서를 더 효율적으로 읽는 것이다. 이번 범위는 번역 품질과 과정의 관찰 가능성까지이며, 인간의 학습 효과는 별도의 후속 실험 대상이다.

우선 구현할 것은 긴 독백형 CoT가 아니라 **문서 메모리, 근거가 연결된 번역 결정, 국소 수정, 중간 산출물 교체 후 재실행**이다. 최근 연구는 추론을 늘리는 것 자체의 효과보다 과제에 맞는 수정·문맥 관리의 중요성을 보여준다. 다만 이 문장은 여러 연구에서 얻은 설계 판단이며, 영→한 수학·물리 논문에서 검증된 결론은 아니다.

구분해야 할 증거는 세 가지다.

1. 모델이 출력한 설명: 무엇을 했다고 말하는가.
2. 실제 실행 기록: 어떤 입력과 메모리를 다음 호출에 전달했는가.
3. 개입 결과: 그 정보를 제거·교체했을 때 번역이 어떻게 변하는가.

2와 3을 확보하면 외부 워크플로우의 기여를 연구할 수 있다. 그것만으로 모델 내부의 이해를 완전히 관찰하거나 우회 경로가 없음을 증명하지는 못한다. 좋은 번역 역시 이해의 유용한 관찰 지표이지 유일한 증거는 아니다.

## 연구별 근거와 적용 판단

### 1. HMS: 번역 추론 로그에서 기능적 절차를 추출

Liu et al., **When Does Reasoning Help in Machine Translation? A Hierarchical Analysis of LRM Reasoning Traces**, EMNLP 2026.

- [논문](https://aclanthology.org/2026.emnlp-main.2499/) · [PDF](https://aclanthology.org/2026.emnlp-main.2499.pdf)
- 확인 범위: 초록, PDF 방법론 §4와 limitations. 코드 실행 없음.
- HMS는 추론을 원자적 단계와 기능 요약으로 바꾸고, 표본별 패턴 유도·통합·재분류를 거쳐 계층적 범주를 만든다. 사전에 정한 인간 번역 절차에 맞춰 분류하는 접근과 차이가 있다.
- 논문은 이해/계획, 번역/초안, 정제/검증이라는 큰 구조와 영역별 차이를 보고한다. 길이와 품질의 관계는 단조롭지 않다.
- 한계: 접근 가능한 추론을 가진 오픈 모델 중심이다. 분류는 분석 도구이며 내부 인지의 정답 라벨이 아니다. 학습된 번역 지표 중심의 결과를 인간 선호나 인과관계로 확대하면 안 된다.
- 적용안: 하네스의 실제 호출·결정·수정 로그를 모은 뒤 기능을 분류한다. 초기에는 수동 범주를 쓰되 `other`를 허용하고, 반복되는 미분류 작업으로 범주를 갱신한다. 이는 HMS의 축소 응용이며 원 논문의 재현은 아니다.

### 2. DelTA: 문서 수준의 상태를 외부에 보관

Wang et al., **DelTA: An Online Document-Level Translation Agent Based on Multi-Level Memory**, ICLR 2025; 최초 공개 2024.

- [논문](https://arxiv.org/abs/2410.08143) · [공식 학회 초록](https://proceedings.iclr.cc/paper_files/paper/2025/hash/285149554f6fbed6e2f9ec72d131bd23-Abstract-Conference.html) · [코드](https://github.com/YutongWang1216/DocMTAgent)
- 확인 범위: 공식 초록과 저장소 README·라이선스 표시. 코드 내부·실행 결과는 미검증.
- 고유명사 기록, 원문/번역문 요약, 장기 문맥, 단기 문맥을 유지·갱신하며 문장 단위로 번역한다. 문서의 일관성과 문맥 의존 표현을 다루는 직접적인 선행 사례다.
- 적용안: 고유명사 기록을 전문 용어·기호·정의 기록으로 확장한다. 각 메모리에 근거 위치, 유효 범위, 변경 이력, 사용한 번역 세그먼트를 연결한다. 논문 내용을 확장한 제안이다.
- 주의: README의 실행 예시 언어 목록에는 한국어가 없다. 영→한 적용 효과는 별도 검증해야 한다. 저장소는 Apache-2.0으로 표시되지만 데이터와 의존성의 권리도 재사용 전에 확인해야 한다.
- 우선순위: 높음. 추가 학습 없이 API 하네스에서 개념을 적용할 수 있다.

### 3. Please Translate Again: 반드시 넣어야 할 단순 대조군

Wu, Aycock, Monz, **Please Translate Again: Two Simple Experiments on Whether Human-Like Reasoning Helps Translation**, EMNLP 2025.

- [논문 및 PDF](https://aclanthology.org/2025.emnlp-main.1031/)
- 확인 범위: 공식 초록. 세부 실험 조건과 비용 일치는 추가 확인 대상.
- 시험한 모델에서 단계적 분해 자체가 성능 향상의 원인이라는 명확한 증거를 찾지 못했고, 재번역·자기수정이 인간을 모방한 단계 프롬프트보다 좋았다고 보고한다.
- 적용안: 직접 번역, 번역 후 한 번 수정, 명시적 중간 상태를 사용하는 번역을 반드시 비교한다. 과정이 그럴듯하다는 이유로 복잡한 설계를 채택하지 않는다.
- 해석 한계: 모든 모델에서 모든 중간 절차가 무용하다는 결론은 아니다. 또한 모델에게 좋은 절차와 사람이 배우기 좋은 절차가 같다는 보장도 없다.

### 4. Test-Time Scaling: 계산을 어디에 쓸 것인가

Li, Ji, Tiedemann, **Test-Time Scaling of Reasoning Models for Machine Translation**, EACL 2026.

- [논문 및 PDF](https://aclanthology.org/2026.eacl-long.133/)
- 확인 범위: 공식 초록.
- 12개 추론 모델을 직접 번역, 강제 추론 연장, 후편집 조건에서 평가했다. 범용 모델의 직접 번역에서 이득은 제한적이고 불일치했으며 자연 종료 이후 강제 연장은 품질을 떨어뜨렸다. 후편집에서는 더 유용했다는 결과다.
- 적용안: 모든 문장에 긴 분석을 강제하기보다 오류가 탐지된 부분에 수정 예산을 배정한다. 수정 횟수, 토큰, 지연과 품질을 함께 기록한다.

### 5. Unlocking Reasoning Capability: 어려운 구간의 구조적 수정

Rajaee et al., **Unlocking Reasoning Capability on Machine Translation in Large Language Models**, WMT 2026.

- [논문 및 PDF](https://aclanthology.org/2026.wmt-main.33/)
- 확인 범위: 공식 초록.
- WMT24++에서 시험한 추론 모델의 명시적 추론이 품질을 떨어뜨렸다고 보고한다. 어려운 구간을 반복 수정하는 구조화된 추론으로 111B 모델을 후학습해 비교 기준보다 개선했다.
- 적용안: 번역 초안을 만든 뒤 문제 구간·대안·선택 근거·수정 전후를 구조화한다. 문제를 해결한 경우에만 변경을 채택한다.
- 한계: 후학습 성과가 API 프롬프트만으로 재현된다는 뜻은 아니다. 하네스 적용은 별도 실험이다.

### 6. PAMT: 어떤 단계가 결과에 기여하는지 보상

Ye et al., **PAMT: Process-Aligned Reinforcement Learning for Multi-Domain Machine Translation**, EMNLP 2026.

- [논문 및 PDF](https://aclanthology.org/2026.emnlp-main.2550/)
- 확인 범위: 공식 초록.
- 15개 영역·4개 번역 방향 분석을 바탕으로 장문·고난도에서의 이점과 용어·문체 제약에서의 이탈을 논한다. 참조 번역의 우도를 얼마나 증가시키는지로 단계별 보상을 구성하고, 결과·형식 보상과 결합한다.
- 적용안: 단계의 존재 자체보다 해당 단계 이후 어떤 오류가 해소됐는지 추적한다.
- 우선순위: 학습 파이프라인 도입은 낮음. 일반 API 하네스는 필요한 우도 계산·RL을 그대로 수행하기 어렵다. 참조 문장 우도도 의미 이해 전체의 척도는 아니다.

### 7. DRT: 수정 과정 자체를 학습 데이터로 사용

Wang et al., **DRT: Deep Reasoning Translation via Long Chain-of-Thought**, Findings of ACL 2025.

- [논문 및 PDF](https://aclanthology.org/2025.findings-acl.351/)
- 확인 범위: 공식 초록.
- 문학의 직유·은유 문장을 대상으로 번역자, 조언자, 평가자의 반복 작업에서 긴 과정 데이터를 만들고 Qwen2.5·Llama3.1 기반 모델을 학습한다.
- 적용안: 초안·비평·수정의 연결을 보존해 이후 재사용 가능한 사례로 만든다.
- 한계: 문학적 비유에 집중한 결과를 일반 논문 독해에 그대로 적용하기 어렵다. 별도 역할의 모델들이 합의해도 정확성의 독립 검증이 되지는 않는다. 모델 학습 성과와 인간 독해력 향상도 별개다.

### 8. Thought Anchors: 개입 검증의 방법론

Bogdan et al., **Thought Anchors: Which LLM Reasoning Steps Matter?**, arXiv 2025, v4.

- [논문](https://arxiv.org/abs/2506.19143) · [프로젝트](https://thought-anchors.com)
- 확인 범위: 논문 초록. 번역 연구가 아닌 방법론적 참고.
- 추론 문장을 의미가 다른 대안으로 바꾼 뒤 이어 생성하여 최종 답의 분포 변화를 측정한다. 계획·불확실성 처리 문장의 큰 영향을 관찰한다.
- 적용안: 외부 메모리의 지시대상·용어 선택·논리 범위를 하나씩 바꾸고 이후 번역만 재실행한다. 이는 원 논문의 CoT 개입을 외부 산출물로 옮긴 제안이다.
- 한계: 비공개 CoT나 사용자용 추론 요약에는 같은 실험을 그대로 할 수 없다. 외부 메모리에 대한 의존성을 내부 신경 계산의 전모로 해석하지 않는다.

## 첫 구현의 범위

아래는 기존 코드 검토 전의 인터페이스 제안이다. 기존 리뷰 스키마를 대체하거나 구현 완료를 뜻하지 않는다.

| 순위 | 기능 | 관측 가능한 산출물 | 채택 이유 |
|---|---|---|---|
| P0 | 실행·입출력 버전 고정 | run manifest, 입력 해시, 모델·프롬프트 버전, 비용 | 동일 조건에서 비교·재실행 |
| P0 | 원문 단위와 번역 정렬 | sentence/paragraph ID와 대응 번역 | 누락·중복과 수정 위치 추적 |
| P1 | 용어·기호·정의 메모리 | 근거 위치, 적용 범위, 선택 번역, 변경 기록 | 문서 일관성과 문맥 재사용 |
| P1 | 초안 후 국소 검토 | 오류 목록, 수정 diff, 채택/기각 | 추가 계산의 실익 관측 |
| P1 | 중간 상태 교체·제거 | fork 실행, 변화한 번역·오류 | 과정의 기여 검증 |
| P2 | 로그 기능 분류 | 단계 라벨과 근거 이벤트 ID | 반복되는 유효 절차 발견 |
| 보류 | CoT 증류·과정 RL | 학습 데이터·체크포인트 | 현재 API 하네스보다 비용·전제 큼 |

기록 형식 예시:

```json
{
  "event_id": "e17",
  "run_id": "run01",
  "stage": "resolve_reference",
  "source_span_ids": ["p3.s2", "p3.s1"],
  "inputs": {"memory_version": "m4"},
  "decision": {
    "expression": "this bound",
    "referent": "equation_12",
    "evidence_span_ids": ["p3.s1"],
    "status": "provisional"
  },
  "output_artifact_id": "reference_map_v2",
  "consumed_by": ["translate_p3"],
  "parent_event_id": "e16"
}
```

위 내용은 합성 예시다. 실제 관측값이 아니다. 출력물의 `consumed_by`는 모델 자기보고가 아니라 오케스트레이터가 실제 전달한 입력에서 기록한다. 근거 문장이 연결돼 있어도 결정이 옳다는 보장은 없으므로 오류 검토가 필요하다.

## 초기 실험 계획

### 데이터와 비교군

우선 30개 안팎의 영어 문단으로 파일럿을 수행하되 통계적 결론용 규모로 간주하지 않는다. 수학·물리 중심으로 정의, 가정, 증명, 결과 해석, 긴 수식 인접 문단, 멀리 떨어진 지시대상을 포함한다. 고정된 개발 문서와 별도의 평가 문서를 둔다. 같은 문서의 문단이 양쪽에 섞이지 않게 한다. 일반 문서나 문학으로 확대할 때는 별도 층으로 보고한다.

| 조건 | 수행 작업 | 묻는 질문 |
|---|---|---|
| A | 직접 번역 | 기본 성능 |
| B | 초안 + 한 번 재검토 | 단순 추가 계산만으로 충분한가 |
| C | 용어·문맥 메모리 + B | 문서 상태가 추가로 기여하는가 |
| D | C + 필요한 구간의 근거·대안·국소 수정 | 구조화된 작업의 이득이 있는가 |

같은 원문·모델 버전·번역 요구사항을 사용한다. 호출 수, 입출력 토큰, 실제 지연을 모두 보고한다. 고정 예산 비교와 실제 운영비 비교를 나눠서 과도한 계산 때문에 좋아진 결과를 구별한다. 하나의 샘플 결과에 의존하지 않고 비용이 허락하는 범위에서 반복 생성한다.

### 품질 측정

- 주 지표: 원문 대비 의미 오류. 누락·추가, 부정·조건·양화사·가능성의 강도, 지시대상, 용어·기호 정의, 수식·참조 보존을 분리한다.
- 한국어 자연스러움은 별도 항목으로 평가하여 의미 정확성의 손실을 유창함으로 상쇄하지 않는다.
- 번역 조건을 가린 상태에서 평가하고, 오류마다 원문 위치와 이유를 남긴다. 일부는 독립 평가자의 불일치를 확인한다.
- 자동 검사: 수식·참조 ID와 원문 세그먼트 커버리지. 문자열 보존 검사는 의미 정확성 검사가 아니다.
- 모델 판정과 자동 번역 점수는 보조 수단으로 쓴다. 같은 모델의 생성·평가가 공유하는 편향을 주의한다.
- 결과 집계: 문서별 중대 의미 오류 수, 수정으로 새로 생긴 오류, 비용·시간. 반복 문단을 독립 문서처럼 취급하지 않는다.

### 중간 단계의 인과적 기여

1. 정상 메모리로 번역한다.
2. 특정 정보만 제거한 메모리로 이후 단계를 재실행한다.
3. 같은 항목을 의미가 다른 그럴듯한 값으로 바꿔 재실행한다.
4. 의미를 유지한 표현 변경을 대조군으로 둔다.
5. 예상한 원문 위치의 번역과 오류가 변하는지 비교한다.

삭제는 품질을 낮추지만 의미 유지 변경은 영향을 주지 않고, 의미 변경은 해당 판단과 연결된 오류를 유발한다면 해당 정보의 기능적 기여를 뒷받침한다. 단순한 프롬프트 길이·형식 변화나 무작위 생성 차이도 통제해야 한다.

최종 번역기가 원문 전체를 다시 볼 수 있으면 잘못된 메모리를 스스로 복구할 수 있다. 따라서 운영 조건(원문 열람 가능)과 진단 조건(중간 표현만 제공)을 분리한다. 전자는 실제 유용성, 후자는 중간 표현의 정보 충분성을 측정한다. 진단 조건의 성공도 인간과 같은 이해 과정의 증명은 아니다. 중간 표현에 완성 번역이 숨겨 들어가면 우회 실험이 되므로 전체 번역 복사를 제한하고 원문 근거와 구조화된 결정만 허용한다.

## 실행 순서와 채택 기준

1. 기존 저장소의 입력 단위·리뷰 스키마·산출물 흐름을 확인하고 로그 삽입 지점을 정한다.
2. A/B 대조군부터 실행하여 현재 오류와 비용을 확보한다.
3. C를 추가하고 문맥·용어 오류가 줄어드는지 본다.
4. D의 추가 이득과 수정 유발 오류를 비교한다.
5. 효과 있는 유형에만 개입 실험을 수행하고 로그를 기능별로 분석한다.

채택 여부는 사전에 정한 품질·비용 기준으로 결정한다. 파일럿 결과를 본 뒤 유리한 기준으로 바꾸지 않는다. 개선이 없으면 해당 단계를 관찰 연구용으로만 남기거나 제거한다. 교육 적용은 이후 학습자가 AI 도움 없이 새 문서를 읽는 전이 평가로 별도 검증한다.
